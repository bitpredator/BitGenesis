# Core Data Model

## Overview

The Core Data Model defines the fundamental objects exchanged between all BitGenesis subsystems.

These objects form the common language of the cognitive architecture.

Every subsystem communicates using these standardized structures.

This ensures consistency, modularity and long-term maintainability.

---

# Design Principles

The Core Data Model follows these principles:

- Immutable whenever possible.
- Explicit over implicit.
- Explainable by design.
- Serializable.
- Versionable.
- Independent from implementation details.

---

# Core Objects

## Event

Represents something that happened.

Produced by:

- Perception
- Runtime
- Tools
- Internal subsystems

Consumed by:

- Kernel

Main Fields

- id
- timestamp
- source
- type
- payload
- trace

---

## CognitiveState

Represents the current internal mental state.

Contains:

- current_event
- active_goal
- active_task
- active_plan
- attention
- execution_status
- timestamp

Managed only by the Cognition subsystem.

---

## MemoryEntry

Represents one stored experience.

Contains:

- id
- event
- decision
- execution_result
- timestamp
- tags

Stored by Memory.

---

## Knowledge

Represents structured information extracted from memories.

Contains:

- concept
- confidence
- relationships
- source_memories

Generated by future Learning modules.

---

## Goal

Represents a desired future state.

Contains:

- id
- description
- priority
- status
- deadline

Managed by Planner.

---

## Task

Represents one executable unit.

Contains:

- id
- goal
- description
- dependencies
- status

---

## Decision

Produced by Reasoning.

Contains:

- id
- conclusion
- confidence
- reasoning_strategy
- supporting_context

---

## Plan

Produced by Planner.

Contains:

- id
- goal
- ordered_tasks
- estimated_cost

---

## Action

Represents one executable operation.

Contains:

- id
- task
- tool
- parameters

---

## ExecutionResult

Represents the outcome of an executed action.

Contains:

- success
- output
- duration
- diagnostics

# Future Objects

The model is intentionally extensible.

Future versions may introduce:

- Attention
- Emotion
- Motivation
- Belief
- Intention
- Reflection
- Prediction

These objects should extend the architecture without breaking compatibility.
